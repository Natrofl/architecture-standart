| F   | Клиент может подать заявку на депозит через интернет-банк и сайт | Ядро MVP: два канала подачи заявки, автоматизация фронта |
|     | На сайте отображаются актуальные (общие) ставки | Требуется онлайн источник ставок, отказ от ручного Excel в перспективе |
|     | В интернет-банке отображаются персонализированные ставки | Предполагает связь с хранилищем ставок, персонализацию |
|     | Заявка с сайта автоматически поступает в систему кол-центра | Необходим API/интеграция между сайт и система кол-центра |
|     | Менеджер кол-центра может предложить особые условия клиенту | Возможность особых офферов по обработке заявок |

|     | После подтверждения открытия депозита клиенту приходит СМС-уведомление | Оповещение через банковский СМС-шлюз, не подрядчик |
|     | Менеджер бэк-офиса подтверждает условия депозита в АБС | Заявка обрабатывается вручную на этапе MVP |

|     | Быстрый отклик интерфейса (миллисекунды) | Критика текущих задержек – особенно для справочников, требуется исправить |
|     | Привычные сценарии и индикация статусов для клиента | Минимум этапов, простое управление статусами заявок |
| R   | Доступность сервисов 99.9% (24/7) | Требование для массового цифрового продукта (интернет-банк, сайт) |
|     | Переключение на резервный ЦОД при сбое | У банка два ЦОД, но сейчас все сервисы в одном — процесс требует улучшения |
|     | Корректная обработка сбоев: заявка не теряется, клиент получает обратную связь | Очередь заявок, уведомления об ошибках, защита данных |
| P   | Серверы интернет-банка масштабируются горизонтально | Основа для будущего роста, в отличие от АБС (только вертикально) |
|     | Время реакции любого сервиса не более 1 секунды | Для MVP — целевой показатель пользовательского комфорта |
| S   | Использование существующих технологий банка (ASP.NET, MS SQL, Oracle, Java, PHP, React) | Обеспечивает быструю поддержку и развитие банком своими силами |
|     | Вся архитектура документируется для расширения | Требуется для масштабирования команды и внедрения новых продуктов |
|     | Решения легко расширять на новые продукты и типы заявок | Открытая архитектура, качественный API, перспектива роста |
| +R  | Все данные клиентов и ставки защищены при передаче (TLS/SSL) | Защита ПДн — критичное законодательное требование |
|     | Хранение и согласование ставок доступно только по ролям (депозиты/кредиты) | Роль доступа реализована либо в АБС, либо в отдельном сервисе |
|     | Никакой прямой интеграции интернет-банка с API АБС | Используется прослойка/очередь, чтобы не перегружать АБС |
|     | MVP совместим только с технологиями, которыми владеет персонал | Исключены "экзотические" стеки, чтобы сократить экспертизу и риски поддержки |
|     | Соответствие ФЗ-152, Положению ЦБ и другим нормам | Без этого MVP не может быть запущен банк-регулятором |
